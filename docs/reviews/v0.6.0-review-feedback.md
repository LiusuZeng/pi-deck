# Pi Deck v0.6.0 — Review Feedback / Pre-Merge Fix List

**Target branch:** `feature/v0.6-unified-work`  
**Purpose:** Treat this document as implementation feedback for the v0.6.0 candidate. Agents may work directly from the items below.  
**Review stance:** The Unified Work architecture is sound. The remaining work is mainly branch integration, release-story cleanup, and removal of a few leftover pre-v0.6 UX semantics.

---

## Executive summary

The v0.6 implementation is directionally correct:

- `PrimaryView` makes Work / Session / Workflow navigation explicit.
- All Work and workspace Work share the same renderer-derived activity model.
- Work remains a projection of session/runtime state rather than a new persisted entity.
- Cross-workspace session opening preserves canonical ownership and runtime identity.
- Saved sessions resume from canonical session identity rather than entering a New Session flow.
- Runtime retention and async navigation races have substantial automated coverage.

However, **do not merge the branch as-is**. Resolve the release blockers below first, then rerun the complete release validation on the final candidate.

## 2. Repair the v0.6.0 changelog and release story

### Problem

The current v0.6 changelog treats several **already-shipped v0.5.5 Parallel Task Sessions features** as new v0.6 additions.

Examples include:

- deterministic Parallel routing
- model-planned task sessions
- task-session panel
- worker model/thinking defaults
- replacement of model-elected `deck_delegate`
- task concurrency/retry/synthesis behavior

Those belong to v0.5.5 history and should not be reintroduced as v0.6 headline features.

### Desired v0.6 release theme

**v0.6.0 — Unified Work**

The release story should center on:

- All Work as the global operational view
- workspace selection opening the same Work surface scoped to that workspace
- Work → Session drill-in
- exact return-to-origin behavior from Session
- workspace organization being optional in ordinary use
- stable default workspace remaining an internal persistence fallback
- explicit primary-view/navigation semantics
- runtime retention across navigation
- canonical saved-session resume

Parallel Task Sessions may be mentioned under compatibility/regression coverage where relevant, but not as a newly introduced v0.6 capability.

### Acceptance criteria

- [ ] `CHANGELOG.md` contains the complete v0.5.5 entry before v0.6.0.
- [ ] v0.6.0 release notes focus on Unified Work.
- [ ] Already-shipped v0.5.5 functionality is not presented as newly added in v0.6.

- [ ] The final release notes remain understandable without knowledge of branch history.

# P2 — Strongly recommended before battlefield dogfooding

## 3. Remove the legacy “Close Work” escape hatch

### Problem

The Work surface still renders an `X` / “Close <scope>” action.

The current close behavior navigates to the internally selected session rather than to a session explicitly selected from Work.

That is a leftover mental model from when Work inbox behaved more like a secondary destination/overlay.

In v0.6, **Work is a primary surface**, not something that should be “closed.”

This creates a confusing path:

```text
All Work
  -> Close
  -> internally selected draft/session
```

The user may never have selected that session from Work.

### Desired behavior

Remove the Work header close action.

Session detail should be entered through an explicit action:

- click a Work row
- New Session
- select/open a known session
- workflow occurrence → session drill-in

Back from Session should return to the recorded Work origin when applicable.

### Required work

- Remove the close button from `ActivityInbox`.
- Remove or simplify `handleCloseWork` if no remaining caller requires it.
- Update component/renderer/E2E tests.
- Ensure focus behavior remains coherent after removing the control.
- Ensure empty Work remains a valid stable primary screen.

### Acceptance criteria

- [ ] All Work cannot be “closed” into an arbitrary selected session.
- [ ] Workspace Work cannot be “closed” into an arbitrary selected session.
- [ ] Work → Session requires an explicit session-opening action.
- [ ] Session → Back still restores the correct Work origin.
- [ ] Empty All Work and empty workspace Work remain usable primary screens.

---

## 4. Make the default workspace genuinely optional in the UX

### Product contract

**Technical workspace: mandatory. Product/UX workspace: optional.**

Every session must still have a workspace owner internally. Global New Session should continue to use the stable default workspace when no explicit workspace scope is requested.

However, a user who has never chosen to organize work into named workspaces should not need to learn or manage the implementation concept “Default Workspace.”

### Current concern

The sidebar still visibly renders the default workspace and labels it `Default`.

That exposes persistence mechanics to users who may only want:

```text
All Work
New Session
Session
```

### Desired progressive disclosure

For a user with no meaningful named-workspace organization:

```text
All Work
----------------
work rows

New Session
```

No workspace-management knowledge should be required.

When named workspaces exist or the user chooses workspace organization, expose workspace controls normally.

### Constraints

Do **not**:

- remove the default workspace from persistence
- make `workspaceId` nullable
- create a second “unscoped session” data model
- rename the default workspace into a new product concept such as General/Scratch/Other unless separately decided
- silently move existing sessions merely to simplify presentation

### Acceptance criteria

- [ ] A fresh/default-only user can start and manage sessions without understanding workspace mechanics.
- [ ] Global New Session still persists ownership to the stable default workspace.
- [ ] Named-workspace users retain full workspace organization controls.
- [ ] Existing workspace/session persistence remains compatible.
- [ ] Relaunch does not create duplicate default workspaces.
- [ ] Hidden/default presentation does not make owned sessions disappear from All Work.

# Architecture invariants — do not regress

Agents working on the feedback above must preserve these contracts.

## Work model

```text
Session/runtime state
        ↓
renderer-derived Work projection
        ↓
scope/status filtering
```

Do not introduce a persisted `WorkItem` entity for v0.6.

## Scope model

```text
All Work
  = Work(scope = all)

Workspace Work
  = Work(scope = workspaceId)
```

These are the same conceptual/rendering model with different scope.

## Navigation model

```text
All Work
  -> Session(origin = All Work)
  -> Back
  -> All Work

Workspace A Work
  -> Session(origin = Workspace A)
  -> Back
  -> Workspace A Work
```

## Workspace ownership

- Every session belongs to exactly one workspace.
- Global creation uses the stable default workspace internally.
- Workspace-scoped creation uses the selected workspace.
- Workspace membership is not inferred from filesystem path.
- Navigating to another workspace must not mutate session ownership.
- Opening Work/session views must not terminate hidden runtimes.

## Saved-session identity

Prefer canonical saved-session identity:

- workspace ownership
- `sessionFile`
- durable Pi `sessionId` where available
- active `runtimeId` when attached

Do not identify a saved session by runtime ID alone.

Known saved-session navigation must not invoke a folder/project picker.

## Async navigation

Preserve generation/staleness guards so an older asynchronous navigation transaction cannot overwrite a newer user action.

## Agent Workflows / Parallel task sessions

v0.6 Unified Work is **not** a redesign of these systems.

They must continue to coexist without being folded into ordinary persisted Work entities.
