# Pi Deck v0.6.1

## Highlights

- This is the first dogfood stabilization patch after **v0.6.0 Unified Work**.
- Session timelines now separate the user-facing response from execution trace through compact **Agent activity** groups, while retaining tool details on demand.
- The composer now supports session-local shell-style `ArrowUp` / `ArrowDown` prompt history without stealing normal multiline cursor movement.
- Work is easier to supervise: active cards stay spatially stable during ordinary progress updates and Completed work is ordered as a deterministic oldest-first follow-up queue.

## Reliability

- Hardened workflow-owned Pi runtimes against destructive public session operations during scheduler-owned allocation, terminal persistence, retirement, reset, archive, and shutdown lifecycle boundaries (#11).
- Kept expanded tool and subagent details fully scrollable above the fixed composer across expansion, collapse, and window resize (#15).

## Work and workspaces

- Prevented same-status Work cards from continuously reshuffling as normal runtime updates arrive (#16).
- Restored workspace overflow actions to a compact vertical menu with separate usable targets (#17).
- Ordered Completed Work by completion timestamp so finished sessions form a predictable FIFO follow-up queue (#19).

## Sessions

- Grouped consecutive thinking/tool execution into secondary **Agent activity** regions, collapsed completed activity by default, kept failures visible, and removed raw serialized tool payloads from the normal collapsed surface (#18).
- Added shell-style prompt history recall with unsent-draft restoration, session-local history, modifier/IME safeguards, and native multiline caret precedence (#20).

## Validation

- The integrated product HEAD immediately before release preparation (`f7c0b41ecd687bbb358d4919909a533af26d0a82`) passed the hosted **Verify desktop app** CI gate after #18 merged.
- The release-preparation commit must still pass hosted CI after version/site/changelog updates.
- Before tagging, run the repository's exact-candidate release gate on the merged `main` commit:

```bash
npm run verify:release
```

- Record the exact final SHA and authenticated real-Pi smoke result before publishing the GitHub Release. Historical v0.6.0 validation evidence is baseline context only and is not reused as v0.6.1 release authorization.

## Known follow-up work

In particular, durable Completed reconstruction across relaunch (#25), Work taxonomy/count cleanup (#22/#24), inline New Session workspace ownership (#23), custom app branding (#26), live real-Pi usage metering (#27), bare URL autolinking (#28), model-picker identity (#30), and the newly observed Parallel parent-turn stall (#32) remain tracked separately.
